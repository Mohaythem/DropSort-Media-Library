## Localization Architecture Findings

1. **The catalog is complete but catalog membership does not guarantee live translation.** All 411 `TextId` values exist in English and Arabic. Controls using `bind_text()` update automatically; controls using one-time `setText(localizer.text(...))`, placeholder assignment, accessible-name assignment, or dynamic render functions require an explicit `language_changed` refresh path. Affected surfaces include Settings selectors/placeholders, Add Movies dynamic status, Personal Library controls, Movie Details dynamic metadata/history, dialogs, and Check Library results.
2. **Application RTL direction previously masked content gaps.** `UiLocalizer.set_language()` updates the application layout direction, but layout mirroring cannot translate hard-coded strings. The 12 proposed direct-source entries identify the remaining audited English accessibility/error copy outside the catalog. RTL layout coverage and translation coverage must remain separate gates.
3. **Dynamic state must remain semantic rather than pre-rendered English.** Check Library now retains its language-neutral state enum plus result DTO in `_last_value` and rerenders through `_refresh_dynamic_text()` on language changes. Add Movies statuses retain `TextId` identifiers where possible. Raw backend/provider/error text is distinct from localized UI framing and must not become the authoritative translated state.
4. **Reconstructed widgets require binding lifecycle ownership.** `UiLocalizer` keys bindings by Python identity, stores weak references, unregisters through `QObject.destroyed`, and defensively checks `shiboken6.isValid()`. This prevents deleted Qt wrappers from accumulating or raising during repeated English/Arabic navigation cycles. Dynamic views must bind each replacement widget and allow destruction to unregister it.
5. **Late-created controls need immediate registration or explicit retranslation.** Add Movies rows, Movie Details file/history rows, Check Library issue rows, and dialog result cards are created after the initial language pass. Each must either bind at construction or regenerate from semantic state when `language_changed` fires; storing a rendered English snapshot is unsafe.
6. **Direct domain text requires a deliberate boundary.** Filenames, paths, movie titles, years, resolutions, ratings, identifiers, TMDB names, and provider-originated proper nouns remain LTR where appropriate. User-facing explanations and accessibility labels around those values should use reviewed localization keys.

- Preserve every named placeholder exactly; placeholders are formatted at runtime.
- Do not translate `DropSort`, `TMDB`, file paths, filenames, IDs, ratings, years, resolutions, or external titles unless product guidance explicitly says otherwise.
- Count-bearing templates currently use a single formatted form. Translator review should flag any Arabic plural-category requirement before implementation changes.
- The 12 `proposed.*` entries are the missing localization handoff. No Arabic wording has been fabricated in this pass.
